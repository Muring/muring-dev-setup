# MuRing Dev Setup 0.1.14

Orca에서 새 Codex 워크트리의 작업 신호가 다른 창으로 전달되는 문제를 피하도록 **Orca Codex 실행 설정** 항목을 추가했습니다.

- Orca가 종료된 상태에서 활성 프로필 설정을 백업하고 `codex --no-daemon`을 저장합니다.
- 실행 중이면 종료 후 재시도를 안내합니다. 기존 세션을 강제 종료하지 않으며, 이미 적용된 설정은 확인만 합니다.
- 기존 실행 인자·환경변수·다른 에이전트 설정을 보존합니다. 사용자 지정 명령은 자동으로 덮어쓰지 않습니다.
- Codex의 옵션 지원 여부와 Orca 설정 형식을 검사합니다. 기존 JSON 및 SQLite 스키마 3을 지원하며, 미반영 JSON 변경·손상·지원하지 않는 스키마는 수정하지 않습니다.

## 사용 방법

새 PC에서는 EXE를 Windows 로컬 폴더에서 실행하고 환경 확인 → 설치 구성 → 설치 진행 순서로 진행합니다. 기존 PC에서는 설치 구성에 **Orca Codex 실행 설정**을 선택한 뒤, Orca를 종료하고 로그인·연동 화면의 **Codex 실행 설정 적용·확인**을 누르세요. 새 EXE 실행만으로 설정이 바뀌지는 않습니다. 적용 후 Orca에서 새 Codex 워크트리를 여세요.

사용자 지정 명령은 로그 안내를 확인해 직접 설정하거나 해당 설치 항목을 선택 해제하세요. 프로필별로 설정되므로 다른 프로필은 별도로 적용해야 합니다. 적용 전 백업은 Orca 설정 파일 옆의 `*.before-codex-no-daemon.*.bak`에 남습니다. 실행 로그는 설치기의 **로그 열기**에서 확인하며, 작업 상태는 `%LOCALAPPDATA%\dev-bootstrap\last-operation.json`에 저장합니다. 다음 버전은 GitHub Releases에서 새 EXE를 받으세요.

## 검증

- 설정 보존·백업·재실행·중간 실패 롤백·손상 거부 검사 15개: Linux 및 동봉 Windows Node에서 통과.
- 현재 PC의 기존 설정 확인 및 실행 중 Orca에 대한 변경 거부 검증 통과. 실제 프로필 DB의 격리 복사본을 수정한 뒤 설치된 Orca 1.4.215의 읽기 코드로 정상 로드되는 것을 확인했습니다. 기존 프로필과 세션은 변경하지 않았습니다.
- 앱 단위 검사 15개, UI 검사 14개, 형식 검사, 설치 순서 회귀 검사 통과. UI 검사는 준비된 사용자 라이브러리 경로로 실행했습니다.

- 최종 EXE를 격리된 Windows 로컬 폴더에서 실행해 버전 0.1.14, sandbox preload·IPC, 실제 WSL 환경 조회, 콘텐츠 미리보기와 새 설치 항목을 확인했습니다. 추출된 ASAR와 리소스 45개의 SHA-256이 빌드·소스와 일치했습니다.

신규 Windows 전체 설치·재부팅·인증, 실제 사용 프로필의 종료·수정·재시작, 다른 Orca DB 스키마와 클라우드 프로필 동기화는 미검증입니다. 서명되지 않은 Windows x64 Pre-release이며 기존 배포 파일은 교체하지 않습니다.
