Claude `/storage-maintenance`, Codex `$storage-maintenance`. `$ARGUMENTS`는 호출과 함께 전달한 대상·모드로 해석한다. 명령 원본 저장소와 진단 대상은 별개다.

기본은 `scripts/storage.py scan`이다. 구현·설정·과거 측정 자료는 필요한 부분만 읽는다. Windows 트리를 WSL의 Python·du로 재귀 탐색하지 않는다. 동봉 PowerShell 5.1 네이티브 수집기에 정확한 Windows 경로를 전달하고 요약 JSON만 받는다. Linux는 `du -x`·`df`를 사용한다. ACL 실패·시간 초과·없는 경로는 0으로 바꾸지 않는다.

1. `scan --config <JSON>`: 지정한 대상별 제한시간으로 읽기 전용 측정, 진행 안내, 부분 결과·스냅샷 저장. 설정이 없으면 제한된 기본 대상만 측정한다. VHD 파일의 논리 크기와 실제 할당량, Linux 내부 사용량, swap을 서로 다른 항목으로 보고한다. 폴더 합계를 볼륨 사용량이나 회수 가능량으로 표현하지 않는다.
2. `compare --period day|week`: 저장된 스냅샷을 비교하고 낮은 여유·증가 알림을 JSON으로 제공한다. 과거 기준값이 없거나 측정 방식·완전성이 다르면 미상이다.
3. `plan --config <JSON>`: 명시한 후보의 정확한 경로·현재 크기·분류·재생성 비용·앱 종료 필요성·보존 판단·검증 지문을 보여준다. 이름 패턴은 후보 발견에만 쓴다. 미사용 버전·오래된 빌드·에이전트가 만든 임시 결과도 소유 근거와 비활성 확인이 없으면 보류한다. 최신 릴리스·롤백본 수와 최소 나이는 설정 가능하다. 캐시 전체를 매번 비우지 않는다.
4. 사용자에게 계획을 보여주고 **정확히 승인한 항목만** 승인 JSON에 기록한다. `apply --plan <JSON> --approval <JSON>`은 기본 dry-run이다. 실제 삭제 승인을 받은 뒤에만 `--execute`를 붙인다. 승인 지문·경로·크기·활성 여부·보호 경로·현재 파일 지문을 다시 검사한다. 실패한 항목을 우회하거나 범위를 넓히지 않는다.

프로젝트 원본·추적 파일·미커밋 파일·AI 이력·인증·활성 VM/swap·Windows Installer/WinSxS는 삭제 금지다. 승인돼도 코드의 보호 규칙을 끄지 않는다. 프로젝트 안의 빌드 산출물은 Git에서 무시되고 추적 파일이 없다는 검증도 필요하다. 앱을 자동 종료하지 않는다. 실제 삭제 승인은 앱 종료 승인과 별개다.

`schedule-plan`은 진단 예약안을 출력할 뿐 설치·활성화하지 않는다. 주기·대상·부하를 보여주고 사용자가 따로 승인한 경우에만 OS 예약 기능으로 등록한다. 예약에 apply를 넣지 않는다.

WSL compaction은 이 명령의 apply 대상이 아니다. 모든 관련 작업 중단에 대한 동의와 복원 가능한 백업을 먼저 확인한 뒤 별도 Windows 세션에서 진행한다. 실행 중인 WSL 세션에서 자동 shutdown을 호출하지 않는다. 절차·설정·승인 형식은 [운영 안내](references/operations.md)를 필요한 모드에 맞게 읽는다.

검증과 실제 수행을 구분해 보고한다. 삭제 전후 볼륨 여유를 별도로 확인하고 WSL 내부 삭제량을 즉시 C: 회수량으로 계산하지 않는다. 측정 파일은 로컬 상태 폴더에 보관하며 내용·인증 데이터는 수집하지 않는다.

Ubuntu 테스트 설치·캐시와 Windows 사용자 Temp도 정확한 후보로만 계획한다. `preserve`에 활성 서버·로그·고유 자료·KB venv/models·사용 중인 Playwright·현재 node_modules와 `.next/dev`를 명시한다. `/tmp/claude-<uid>` 같은 공유 작업 루트는 `root_only: true`로 전체 삭제를 막고, 완료된 소유 작업의 재생성 가능한 하위 산출물만 별도로 검증한다. 보존 경로를 포함한 상위 후보도 거부한다.

후보에는 `regenerable_verified`와, 에이전트 임시 산출물인 경우 `owner_task_completed` 근거가 필요하다. 이름·나이·실행파일 매칭 0건은 소유권이나 비활성 증명이 아니다. Linux cwd/exe/fd/maps와 Windows 실행파일 관측·핸들 검증 범위를 구분해서 보고한다. 전체 핸들 검증이 없는 Windows 상태는 미상으로 보류한다. apply 직전 manifest와 사용 상태를 다시 검사하며 활성·미상 항목은 건너뛰고 잠긴 파일의 삭제 실패는 중단·부분 결과로 남긴다. 프로세스를 종료하거나 검사 우회로 재시도하지 않는다. 실행 결과의 `space_before`·`space_after`는 Linux 내부와 Windows host를 분리한 관측값이며 동시 작업의 영향도 포함한다.
